# Кейс 3 «Онлайн-чаевые» — ВПОТОКЕ

Платформа онлайн-чаевых для сети «Вкус-Сервис»: клиент сканирует QR на чеке,
выбирает чаевые и платит, платформа ведёт мерчантов, официантов, платежи и отчётность.

Этап 1 (самостоятельная подготовка): 30.10 – 07.11. Сдаём презентацию (6–8 слайдов)
и приложение (10–15 страниц) в PDF.

## С чего начать

1. Прочитай руководство для своей роли:
   [аналитик](docs/guides/analyst.md) · [разработчик](docs/guides/developer.md) ·
   [презентатор](docs/guides/presenter.md) · [архитектор](docs/guides/architect.md).
2. Пролистай [архитектурные решения](docs/README.md). Это 9 коротких ADR: в них закрыты
   противоречия в материалах кейса, и на них ссылаются все остальные документы.
3. Перед любой работой с ИИ открой [журнал промптов](docs/ai-journal.md). Записываем каждую итерацию.

## Команды

```bash
# данные не менялись (скриншот для приложения, раздел E)
cd prototype/01_данные && md5sum -c MD5SUMS

# проверить расчёты аналитика и связи исходных CSV (без записи файлов)
python3 docs/checks/analyst_data.py

# пересобрать схемы после правки генераторов
cd diagrams && python3 build_system.py && python3 build_states.py && python3 build_er.py
convert -density 192 system.svg system.png   # так же для states и er

# запустить прототип (после доработки по docs/guides/developer.md)
export TIPS_HMAC_SECRET=demo-secret-k3
python3 prototype/04_прототип.py qr.json
```

## Правила команды

- **Ветка для сдачи — `team_N_case_3`** (N — номер команды). Работаем в ней или в своих ветках с merge в неё.
- **Секреты не коммитим.** `demo-secret-k3` — демо-ключ организаторов, им подписаны seed-данные;
  в коде его нет, только в переменной окружения.
- **`case/` и `prototype/01_данные/` не редактируем.** Свои версии шаблонов кладём в `docs/`.
- **ИИ — ассистент, а не автор.** Всё, что сделано с ИИ, проверяем, перерабатываем и записываем
  в журнал. На защите каждый объясняет любую строку своего кода и любое решение.
- **Противоречие в материалах кейса** — не выбираем молча, а записываем решение в ADR.
