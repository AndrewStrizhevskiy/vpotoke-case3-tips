# ADR-007. Отчётность: что и как считается

Статус: черновик (архитектор), 2026-11-02.

## Контекст

- Пример отчёта по m_001 в `09_reports.md` (550.00 / 4 / 0.75) не сходится с `payments.csv`,
  а критерий приёмки требует «данные сходятся с payments.csv».
- Не сказано, какие статусы входят в каждую метрику. Чаевые по DECLINED и CANCELED
  никто не получил, а `tips_total` по всем статусам у m_001 дал бы 611.20 вместо 414.85.

## Решение

| Метрика | Формула | По каким статусам |
|-|-|-|
| payments_count | count(*) | все попытки за период |
| success_count | count(SUCCESS) | SUCCESS |
| tips_total | sum(tip) | только SUCCESS |
| avg_tip_pct | avg(tip / amount × 100) | только SUCCESS |
| avg_tip_amount | tips_total / success_count | только SUCCESS |
| success_rate | success_count / payments_count | все |
| top_day | день с наибольшим tips_total | только SUCCESS |

Период задаётся по `timestamp` в UTC, границы `[from, to]` включительно.
Округление: суммы до 0.01, доли до 0.01, `ROUND_HALF_UP`.

### Контрольные значения (ноябрь 2025, `payments.csv`)

**Мерчант m_001:** 6 платежей, 5 SUCCESS, `tips_total` = 414.85, `avg_tip_pct` = 9.00,
`success_rate` = 0.83.

**Официант e_001:** 2 платежа (p_0001, p_0055), оба SUCCESS, `tips_total` = 83.60,
`avg_tip_amount` = 41.80, `top_day` = 2025-11-03 (51.75 против 31.85).

**m_001 по дням:**

| date | tips_total | payments_count | avg_tip_pct |
|-|-|-|-|
| 2025-11-01 | 245.90 | 3 | 10.00 |
| 2025-11-03 | 168.95 | 3 (1 DECLINED) | 7.50 |

### Граничные случаи

Предложены аналитиком в PR #1, приняты архитектором 2026-11-03:

- **Пустой период** (нет попыток): `tips_total = 0.00`, `payments_count = 0`, `success_rate = 0.00`,
  `avg_tip_pct`, `avg_tip_amount`, `top_day` — `null`. Схема Report не допускает `null` в `success_rate`.
- **Есть попытки, но нет SUCCESS:** `tips_total = 0.00`, средние и `top_day` — `null`, `success_rate = 0.00`.
- **Равные суммы по дням:** `top_day` — самый ранний день (UTC).
- **Дни без попыток** в `daily` не включаются; пустой интервал даёт `daily: []`.
- **Период.** `period` в схемах имеет вид `YYYY-MM`, поэтому отчёты мерчанта и официанта запрашиваются
  в пределах одного календарного месяца, иначе 400 `VALIDATION_ERROR`; отчёт по дням интервалом не ограничен.
  Произвольные интервалы — задача версии 2 (нужен другой формат `period`).
- Реализация — команда `report` прототипа, тест T3-12.

### Доступ

- Мерчант видит отчёты только по своему `merchant_id`.
- Официант видит только свои чаевые (`employee_id` из токена, а не из параметра запроса),
  чужой `employee_id` → 403 `ACCESS_DENIED`.
- Администратор видит всё. Клиент отчётов не видит.

## Последствия

- Пример в `09_reports.md` заменяем контрольными значениями из этого ADR.
- Тест на отчёт: расчёт по m_001 должен дать 414.85 / 6 / 0.83.
