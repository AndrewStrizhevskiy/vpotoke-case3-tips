# ADR-006. Каталог ошибок

Статус: черновик (архитектор), 2026-11-02.

## Контекст

Приложение (B.2) ссылается на ошибки «из 08_errors.md», но в этом файле лежит ER-модель.
Каталог ошибок пришлось составить самим. Первые четыре строки взяты из приложения без изменений.

## Решение

`retryable` отвечает на вопрос: может ли **повтор того же действия** привести к успеху.
В скобках сказано, что именно нужно повторить.

| Ситуация | error_code | HTTP | retryable |
|-|-|-|-|
| Подпись QR не совпала или нет `sig` | INVALID_QR | 422 | нет |
| QR истёк | QR_EXPIRED | 410 | да (новый QR у официанта) |
| nonce погашен (по QR уже есть SUCCESS) | QR_USED | 409 | нет |
| Мерчант не ACTIVE (BLOCKED или PENDING) | MERCHANT_BLOCKED | 403 | нет |
| `receipt_id` не совпадает с QR | RECEIPT_MISMATCH | 422 | нет |
| `base_amount` не совпадает с реестром чеков | AMOUNT_MISMATCH | 422 | нет |
| `tip_pct > 50` или `tip_amount > base × 0.5` | TIP_OUT_OF_RANGE | 422 | да (исправить чаевые) |
| `base_amount ≤ 0` или `> 1 000 000` | AMOUNT_OUT_OF_RANGE | 422 | нет |
| `amount_total > 2 000 000` | AMOUNT_OUT_OF_RANGE | 422 | нет |
| Тот же `idempotency_key` и то же тело запроса | — (вернуть существующий платёж) | 200 | — |
| Тот же `idempotency_key`, другое тело | IDEMPOTENCY_CONFLICT | 409 | нет |
| По QR уже есть платёж в CREATED или PENDING | PAYMENT_IN_PROGRESS | 409 | да (дождаться итога) |
| Эмулятор вернул 8 | CARD_DECLINED | 402 | да (другой способ оплаты) |
| Эмулятор вернул 9 | GATEWAY_TIMEOUT | 202, статус PENDING | да (опросить статус) |
| Сверка закрыла PENDING по таймауту | GATEWAY_TIMEOUT | — (статус DECLINED) | да (новая попытка) |
| Отмена из CREATED | — | 200, статус CANCELED | — |
| Отмена из PENDING | CANCEL_NOT_ALLOWED | 409 | нет |
| Отмена из SUCCESS | CANCEL_NOT_ALLOWED | 409 | нет |
| confirm или cancel для платежа в финальном статусе | PAYMENT_STATE_CONFLICT | 409 | нет |
| QR или платёж не найден (запрос с верной подписью) | NOT_FOUND | 404 | нет |
| Неверный формат запроса | VALIDATION_ERROR | 400 | нет |
| Нет прав (RBAC), например чужой отчёт | ACCESS_DENIED | 403 | нет |
| Превышен rate limit | RATE_LIMITED | 429 | да (после `Retry-After`) |

### Формат ответа

```json
{
  "error_code": "QR_EXPIRED",
  "message": "Срок действия QR истёк",
  "retryable": true,
  "details": {"qr_id": "qr_001", "exp": "2025-11-01T23:59:00Z"}
}
```

В `details` не попадают секреты, подписи и полные реквизиты.

### Что видит клиент (экран 4)

| Код | Сообщение |
|-|-|
| SUCCESS | «Спасибо! Чаевые отправлены» |
| CARD_DECLINED | «Оплата не прошла, попробуйте другой способ» |
| GATEWAY_TIMEOUT | «Обрабатываем, проверьте через минуту» |
| QR_EXPIRED | «QR устарел, попросите официанта новый» |
| остальные | «Не удалось открыть оплату» (подробности только в логах) |

## Последствия

- `INVALID_QR` намеренно не уточняет причину: атакующему не нужно знать, что не так с подписью.
- 402 на отказ шлюза и 202 на таймаут совпадают с TODO в `05_api_schemas.yaml` (confirm: 200, 402, 409).
