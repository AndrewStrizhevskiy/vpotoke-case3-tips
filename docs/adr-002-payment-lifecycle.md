# ADR-002. Жизненный цикл платежа, отмена и погашение nonce

Статус: черновик (архитектор), 2026-11-02.

## Контекст

- В матрице переходов `07_payment_emulator_template.md` есть строка `PENDING → CANCELED`,
  а правило P-4 и тест T3-5 требуют, чтобы отмена из PENDING возвращала 409.
- По ER-модели на один QR допускается несколько попыток платежа (1:N).
  Если гасить nonce при первой попытке, после DECLINED клиент не сможет заплатить повторно.
- В `payments.csv` 10 платежей застряли в PENDING, и правила выхода из этого статуса нет.

## Решение

### Состояния

| Статус | Смысл | Финальный |
|-|-|-|
| CREATED | Платёж создан, суммы зафиксированы, в шлюз ещё не отправлен | нет |
| PENDING | Клиент подтвердил оплату, запрос ушёл в шлюз, ответа пока нет | нет |
| SUCCESS | Шлюз подтвердил списание | да |
| DECLINED | Шлюз отказал, или сверка закрыла платёж по таймауту | да |
| CANCELED | Клиент или система отменили платёж до отправки в шлюз | да |

### Матрица переходов

| Из | В | Условие | Кто (actor) |
|-|-|-|-|
| — | CREATED | `POST /tips` прошёл проверки Q и P | client |
| CREATED | PENDING | `POST /payments/{id}/confirm` | client |
| PENDING | SUCCESS | эмулятор вернул h = 0..7 | system |
| PENDING | DECLINED | эмулятор вернул h = 8 (`CARD_DECLINED`) | system |
| PENDING | PENDING | эмулятор вернул h = 9 (таймаут), ждём сверку | system |
| PENDING | DECLINED | сверка: 15 мин без ответа (`GATEWAY_TIMEOUT`) | system |
| CREATED | CANCELED | `POST /payments/{id}/cancel` | client |
| CREATED | CANCELED | истёк `exp` у QR или 15 мин без confirm | system |
| PENDING | CANCELED | **запрещено**: 409 `CANCEL_NOT_ALLOWED`, запрос уже в шлюзе | — |
| SUCCESS | CANCELED | **запрещено**: 409 `CANCEL_NOT_ALLOWED`, возвраты вне проекта | — |
| финальный | любой | запрещено: 409 `PAYMENT_STATE_CONFLICT` | — |

Почему отмена из PENDING запрещена: шлюз мог уже списать деньги.
Если отменить у себя, а списание пройдёт, клиент заплатит, а официант не получит чаевые.
Безопасный выход из PENDING даёт только шлюз или сверка.

### Погашение nonce и блокировка QR

- Пока у QR есть платёж в CREATED или PENDING, QR **заблокирован**.
  Новая попытка с другим `idempotency_key` получает 409 `PAYMENT_IN_PROGRESS` (retryable).
- nonce **гасится только при переходе в SUCCESS**. После этого Q-3 возвращает 409 `QR_USED`.
- После DECLINED или CANCELED QR снова свободен до `exp`: клиент может попробовать ещё раз.

### Аудит

Каждый переход — отдельное событие AuditEvent (связь 1:N).

| action | Переход |
|-|-|
| payment_created | — → CREATED |
| payment_submitted | CREATED → PENDING (действия нет в подсказке 08, добавлено) |
| payment_confirmed | PENDING → SUCCESS |
| payment_declined | PENDING → DECLINED |
| payment_canceled | CREATED → CANCELED |

`actor`: `client` — действие клиента, `system` — шлюз, сверка или автоотмена,
`officer` — администратор платформы при ручном разборе инцидента.
Ручная смена статуса платежа администратором в этом проекте не предусмотрена.

## Последствия

- Тест T3-5 разбивается на два шага: отмена из CREATED даёт 200 и CANCELED,
  отмена из PENDING даёт 409. Второй шаг ловит строку матрицы, которая выглядит как противоречие.
- Нужен фоновый процесс сверки. В прототипе он запускается командой с параметром `--now`.
- Повторная оплата после отказа возможна, но с тем же QR эмулятор снова вернёт DECLINED (ADR-001).
